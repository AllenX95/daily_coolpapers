# Daily Cool Papers：两阶段分类与方向出清 PRD

- 版本：v0.1
- 日期：2026-10-10（北京时间）
- 状态：C1/C2 与 C3 历史处理工具已实现；40 篇人工校准待开展，模型准确率尚未验证。
- 目标：让方向中的论文可见，用低成本初筛与 Pro 精筛减少人工候选，并支持入选后的移出与恢复。
- 实现原则：沿用 Flask、SQLite、任务队列、模型配置和 Prompt 管理；先完成可用闭环，不引入新基础设施。

本方案更新旧 PRD 中“投资主题仅手动归档”和“所有 possible 自动执行摘要评估”的约定，其余既有能力沿用。

## 1. 背景与范围

2026-10-10 的只读检查发现：论文库有 6,364 篇论文，关注方向已有 650 项明确匹配，涉及 597 篇论文；仍有 2,283 项待确认，涉及 1,821 篇论文。同一论文可对应多个方向，以上两组论文可能重叠。投资主题的论文关联为零。

空列表和候选过多来自不同问题：

- 关注方向页面只展示定义，缺少按方向查看论文的入口；投资主题目前只支持手动归档，没有自动分类。
- 初筛的 `possible` 同时表示“技术邻近”和“摘要不足”，容易把弱关联论文积压为人工候选。
- 当前分类使用 Flash，Pro 只用于全文评估，没有候选精筛阶段。
- 入选论文可在详情页单独否决或移除主题，但缺少集中出清入口。

本期包括：方向论文列表、两阶段分类、研究与投资两类范围的自动归类、人工处理和批量出清。暂不做新方向生成、自动下载全文精筛、模型训练、向量检索、定期全库重评和复杂置信度校准系统。

本文“研究方向”对应现有“关注方向”；“投资方向”对应现有“投资主题”。二者保留独立名称、定义和论文关联，不按同名自动合并。

## 2. 核心流程

```text
论文入库
  → Flash 根据启用的研究方向、投资主题初筛
      → 明确匹配：自动入选
      → 有具体关联但存在关键疑点：进入 Pro 精筛
      → 不相关：保留论文，不加入方向
  → Pro 精筛候选
      → 入选：加入对应方向
      → 排除：结束该项候选
      → 仍待确认：进入人工待分类列表
  → 用户阅读已入选论文
      → 保留，或移出指定方向；误操作可恢复
```

判断单位始终是“论文 × 研究方向／投资主题”。某一方向被排除不影响其他方向，也不删除论文、评估或收藏。

Flash 明确匹配保留自动入选能力；首版不要求所有论文经过 Pro。人工确认与人工移出优先于两阶段模型判断。

## 3. 页面与交互

### 3.1 方向目录与论文列表

研究方向、投资主题目录均显示“已入选 N 篇”和“待处理 N 篇”，点击进入该方向论文列表。待处理数包含等待精筛和等待人工确认的论文，子状态分开展示。

方向论文列表包含“已入选／待处理／已移出”三个视图，支持日期筛选与分页，默认跨所有抓取日期展示。每篇论文展示标题、原始摘要摘要段、入库日期、归类理由、判断来源及置信等级（有精筛时）。已入选列表允许单篇或本页勾选后批量移出。

投资主题开始参与自动分类，以主题说明作为范围定义。未填写说明的主题仍可手动归档，但不参与自动分类，并在目录提示补充说明。用户仍可手动加入主题，无需先完成全文评估。

### 3.2 待分类列表

沿用顶部“待分类”tab，加入研究方向／投资主题筛选，以及“等待精筛／需人工确认”状态筛选。

- 等待精筛：显示初筛理由和任务状态，可批量触发 Pro；已有运行任务时显示进度。
- 需人工确认：显示初筛与 Pro 的理由、关键疑点，支持批量确认或否决。
- 两种状态都允许人工直接处理，无需等待模型；已经人工处理的项不会被随后完成的任务覆盖。
- 全选仅作用于本页，显示所选分类项数量。同篇论文的不同方向分别勾选。

模型精筛已排除的项不继续占用人工队列，可从论文详情查看理由。已移出视图保留人工移出和 Pro 排除的来源，方便复查与恢复。

### 3.3 配置与任务反馈

LLM 设置区分“分类初筛模型”和“分类精筛模型”，默认分别选择现有 Flash、Pro 配置；Prompt 管理区分两个阶段。

每日新论文默认自动精筛 `possible`。未配置精筛模型时，保留现有人工待确认流程并提示配置；失败项显示“精筛失败，可重试”，不视为不相关。任务中心沿用现有进度与失败信息，展示初筛数量、精筛数量、入选／排除／人工待确认数量和已有调用用量。

## 4. 分类规则与 Prompt

### 4.1 Flash 初筛：有依据地保留相关论文

输入为标题、原始摘要、Subjects、类目，以及各研究方向和投资主题的定义。不使用 AI 摘要代替原始摘要。

| 输出 | 判断规则 | 后续 |
|---|---|---|
| `matched` | 核心贡献直接相关，或关键支撑技术对该方向有清楚、实质的作用 | 自动入选 |
| `possible` | 已找到具体关联，但有一个影响归类的关键疑点需要进一步判断 | Pro 精筛 |
| `unmatched` | 不相关，或仅有关键词／应用背景重合，缺少实质联系 | 不入选 |

Prompt 必须明确：仅“使用了检索”“使用了 Agent”“可能未来有帮助”不足以进入候选；摘要未描述实验细节，也不应自动降为 `possible`。候选必须说明关联证据和疑点，不能只回答“摘要不足”。

投资主题判断的是技术与主题的关联，不要求论文已经具备成熟商业化路径。商业潜力可在已有摘要／全文评估中另行判断，不作为主题归类的必要条件。

### 4.2 Pro 精筛：解决疑点，不默认否定候选

按论文汇总其候选方向，一次精筛请求判断多个候选，减少重复输入。输入原始元信息、候选定义、Flash 理由和疑点；可提供已有成功全文评估中的相关结论作为辅助信息，首版不为精筛自动下载或转换全文。

Prompt 的核心要求：

> 根据论文贡献和方向定义独立判断，再核对初筛提出的关联与疑点。不得因为论文来自待确认队列就预设不相关。摘要已明确支持技术联系时，可以确认入选；缺少全文实验细节、商业验证或某个定义词语，不构成自动排除理由。排除应指出具体范围错配或关联依据不足。明确区分论文证据、合理解释与尚未证实的推测。

| 精筛结果 | 使用条件 |
|---|---|
| 入选 | 有清晰的直接贡献或关键支撑关系，现有信息足以归类 |
| 排除 | 初筛关联只是背景、工具使用、同词异义，或明确偏离范围 |
| 仍待确认 | 确有具体关联，但剩余疑点会实质改变归类，当前信息无法解决 |

输出包括：目标类型与 ID、结果、关键证据、简短理由、置信等级（高／中／低）；仅仍待确认时填写关键疑点。Flash 输出保留原始判断，不被 Pro 结果覆盖。

置信等级表示模型对本次归类的把握，不等同于论文质量或真实正确率。首版不设未经验证的“80% 入选”阈值，也不规定所有入选必须为高置信；中置信但证据足够的判断可以入选。低置信的归类判断进入人工确认。

### 4.3 典型边界

| 论文贡献 | 方向 | 预期判断 |
|---|---|---|
| 推理服务调度、批处理与吞吐优化 | AI Infra | 明确匹配，不因缺少商业验证降级 |
| Agent 执行轨迹监控、恢复或权限机制 | Agent Runtime | 明确匹配 |
| 硬件验证综述仅提到 Agent 编排、检索 | Agent Runtime／AI Memory | 不凭关键词入选；只有明确涉及范围内技术贡献时才保留候选 |
| 物理多智能体机器人操作 | Agent Runtime | 不因出现 multi-agent 就匹配软件执行环境 |
| 与实时交互紧密相关的时间建模机制 | Interactive Model | 可按关键支撑关系入选，不要求逐字覆盖方向定义 |

这些例子用于说明边界，不要求模型按标题硬编码判断。

## 5. 入选后出清

用户从已入选列表或论文详情移出某个方向，理由可选“范围不符／仅弱相关／判断错误／其他”，备注可选；批量移出可共用一个理由。

- 移出后从该方向已入选列表消失，历史理由和模型结果保留，其他方向不变。
- 人工移出形成明确的排除决定，后续抓取、初筛或精筛不会自动重新加入。
- “恢复”撤销该方向的移出决定，恢复移出前的有效判断；也允许人工直接确认重新加入，不调用模型。
- 对 Pro 排除项点击“恢复入选”时，保存人工确认，优先于 Pro 排除结果；不修改原始精筛记录。
- 已有全文评估如果指出明确范围不符，可以生成“建议移出”，由用户确认；不因论文低分、商业风险或模型一般性批评自动出清。

首版的“建议移出”展示在论文详情与所属方向列表，不新增自动扫描任务。对已有全文结果复用已有信息；需要模型判断时，用户在已入选论文详情点击“Pro 复核此方向”，复用精筛能力。明确排除时先生成建议，由用户确认移出；仍待确认或调用失败均保留已有归类。

## 6. 实现边界

初筛、精筛、人工决定分开保存；页面的有效归类按“人工决定 → 成功的候选 Pro 精筛结果 → Flash 明确匹配”的优先级计算。候选经 Pro 判断仍待确认时不自动成为正式分类；失败不改变上一有效结果。已入选论文的 Pro 复核记录作为建议，不直接参与有效归类计算。人工决定最高优先级。

现有分类逻辑只补缺失或失败结果，不重写成功结果。新增独立精筛操作与结果记录，不通过替换初筛模型、覆盖原始结果实现。对投资主题补充自动判断来源和人工移出状态，沿用现有主题关联作为列表数据入口；已有手动归档按人工确认处理。

保留必要的模型输出校验：目标属于本次请求、状态合法、理由可用。批量人工操作沿用现有事务、CSRF 和状态检查，重复任务沿用现有排重能力。无需另建通用工作流框架、锁服务、多版本事件系统或自定义重试体系。

无启用且定义完整的分类目标时，保留现有“全部新论文执行摘要评估”的行为。有分类目标时，自动摘要评估改为针对已入选论文执行；等待 Pro 的论文先完成精筛，只有仍需人工确认的项留在队列。任一方向入选即可按论文去重执行缺失摘要评估；Pro 入选或人工确认也触发这一后续步骤，已有成功摘要评估则复用。用户仍可对任意论文手动执行摘要评估。

## 7. 历史数据与上线顺序

1. 先提供方向论文列表，让已有明确匹配和手动归档立即可见；不把历史数据全部重新分类。
2. 配置两个阶段的模型与 Prompt，在小批历史样本上验证规则，再启用每日新论文精筛。
3. 历史待确认由用户按方向、日期选择后分批精筛；运行前显示论文数、分类项数和预计逻辑调用数。只处理所选候选，沿用任务中心查看结果及重试失败项。
4. 投资主题因无历史自动结果，提供按日期选取论文的补分类入口；默认先小范围运行，不自动全库调用。
5. 修改 Prompt 不自动重跑已有成功分类。批量 Pro 精筛只处理待确认候选；历史已入选项可在详情页单项复核，历史 `unmatched` 可人工确认加入。本期不新增对已匹配／未匹配结果的批量重评入口。

## 8. 轻量验证与验收

开发只验证影响用户判断和数据的关键路径，复用现有测试设施：

1. 两类方向的数量、列表与筛选一致，同篇多方向独立显示。
2. 初筛三种结果进入正确分支；Pro 入选、排除、仍待确认正确落地，失败可重试。
3. 人工决定覆盖模型结果；运行中的精筛不能覆盖后来提交的人工决定。
4. 单篇／批量移出与恢复生效，其他方向及原始评估保留。
5. 自动摘要评估按最终入选门控；没有分类目标时保留现有行为。
6. 用一个隔离浏览器流程验证筛选、勾选、精筛状态和移出／恢复，检查桌面及窄屏布局。

模型效果采用一次小样本人工核对，建议约 40 篇，覆盖明确匹配、待确认、未匹配以及不同方向；以清楚相关、弱关联和同词异义案例为重点。记录人工是否认可判断、待确认如何分流，以及调用用量。该样本用于调整规则，不宣称得到稳定准确率。

上线判断：方向论文能够找到，Pro 能把候选分流为有理由的结果，人工队列不只是换了名称；若入选被集中误判为排除，先修正 Prompt 再扩大历史处理范围。不预设强制入选比例或队列减少比例。

不新增压力测试、全面截图矩阵、大规模付费模型基准、穷举异常测试或新的测试框架；仅在实际发现问题时补充对应验证。

| C1：可见与出清 | 两类方向的论文列表、数量、批量移出及恢复 | 已有论文可查看，人工修正形成闭环 |
