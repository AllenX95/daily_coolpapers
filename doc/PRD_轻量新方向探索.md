# Daily Cool Papers：轻量新方向探索 PRD

- 版本：v1.0
- 日期：2026-10-08（北京时间）
- 状态：E0–E2 已实现并完成隔离验证；E3 四周人工试用待开展。见 [实施与验收报告](EXPLORATION_RELEASE_REPORT.md)。
- 目标：从已有论文库中发现值得继续跟踪的候选研究方向，补足已有关注方向分类的覆盖盲区。
- 适用范围：现有 Flask、SQLite、任务队列、Prompt 管理及 LLM 调用账本。
- 首版原则：手动按周运行、固定探索预算、只读元数据与原始摘要、少量候选、人工确认。

## 1. 背景与已确认决策

当前流水线根据已有关注方向进行分类。有启用方向时，只有 `matched` 或 `possible` 的论文进入自动摘要评估；`unmatched` 保留在库中。分类输出必须覆盖已有方向，不能自由生成新方向。每日全量采集扩大了元数据覆盖，但没有解决未知方向的发现问题。

本功能增加独立探索任务，不改变现有分类契约和每日流水线门控。它同时观察未匹配论文和已有方向中的边缘研究，不要求先定义方向再寻找论文。

已确认的产品决策：

1. 每周探索默认最多 40 篇，输出最多 3 个候选方向；证据不足时允许零候选。
2. 阅读 star 只作为热度辅助指标，不代表技术质量、读完人数或独立认可人数。
3. 使用标题、原始摘要、作者、Subjects 和类目，不下载 PDF，不转换 Markdown，不执行全文评估。
4. 四批提取加一次汇总，正常最多 5 次逻辑模型调用。不逐篇执行现有完整摘要评估。
5. 首版手动触发，先运行四周验证价值；不新增自动调度、外部通知或外部搜索。
6. 模型只提出候选；用户确认后才创建关注方向。投资主题、收藏、团队跟踪及缓存等级不自动改变。
7. 不引入向量数据库、嵌入模型、语义聚类服务或独立任务系统。

## 2. 使用流程

```text
打开新方向探索页面
  → 预览最近七天可探索论文、选样构成及调用上限
  → 点击生成周报
  → 固化论文、方向、观察候选与模型配置快照
  → 分批提取研究问题／方法／能力
  → 汇总、去重并校验候选引用
  → 阅读最多三张候选卡片
  → 继续观察／加入关注方向／忽略
```

目标审阅时间为每周约 10 分钟，这是产品目标，需由四周试用验证。

## 3. 数据范围与选样

### 3.1 时间及资格

- 默认窗口为最近七个完整北京时间自然日，不含当天；页面明确展示起止日期。查询边界转换为 UTC 半开区间。
- 以首次入库时间限定窗口，避免旧论文因重复抓取再次成为新样本。当前有源类目覆盖的论文才可能进入探索；周报不宣称覆盖所有学术研究。
- 标题与原始摘要完整，按 arXiv ID 去重；不使用已有 AI 中文摘要替代原始摘要。
- 在本次启用方向快照下聚合已有分类结果及人工判断，复用现有有效方向判定语义。
- 部分方向结果缺失或失败且无法确定有效聚合状态的论文，记入“分类待完成”，不当作 `unmatched`；探索任务不补发方向分类请求。
- 无启用方向时，论文进入“未设方向探索池”，无需分类；周报明确标注这一情况。
- 仅排除在历史成功探索提取中已消费的 arXiv ID。仅预览、入队或失败尝试不永久排除论文。
- 题名或摘要超出单请求可用上下文的论文单独计数并跳过，不静默截断后宣称完整阅读。

### 3.2 默认样本构成

| 样本组 | 默认数量 | 选择规则 | 目的 |
|---|---:|---|---|
| 热度探索 | 20 | 未匹配池中按同类目、同源日期热度百分位选取 | 借助读者兴趣发现已有范围之外的研究 |
| 随机探索 | 10 | 剩余未匹配池按类目分层随机抽样 | 保留低热度与小众研究机会 |
| 边缘探索 | 10 | `possible` 优先，其次 `matched`，按类目分层抽样 | 发现已有方向边缘或内部的新分支 |

选样顺序为热度、随机、边缘，后续组排除前组已选论文。同一论文只出现一次。

跨类目论文按类目代码字典序确定唯一抽样归属，防止因跨类目获得更多随机抽样机会；模型输入保留完整类目集合。分层抽样轮流从各非空类目取一篇，再循环，使用固化随机种子保证可复现。

样本组不足时从其他组剩余合格论文补足：先轮流补未匹配池的热度与随机名额，再补边缘池。没有启用方向时 30 篇热度、10 篇随机。全池不足 40 篇时按实际数量运行，不扩大时间窗口，不重复论文；无合格论文不调用模型。

### 3.3 阅读热度口径

当前项目的 `reading_stars = pdf_clicks + kimi_clicks`，是本项目的组合指标。个人星标列表与公共按钮计数属于不同概念，不能把组合值表述为收藏人数。

官方说明将 PDF／Kimi 数字解释为按钮点击计数，并将个人星标描述为点击后的阅读记录。当前公开前端分别用浏览器本地记录抑制重复点击，同一浏览器点击两种按钮可分别贡献一次；服务端去重、防刷及站内最终排序公式尚未确认。

依据：[papers.cool 官方说明](https://github.com/bojone/papers.cool/blob/main/README.md)、[公开前端脚本](https://papers.cool/static/cool.js?v=1.5.2.2)。核对日期为 2026-10-08；实施时如口径变化需更新说明。

- 按相同类目、相同源列表日期的全部已保存去重论文计算百分位，不仅在未匹配子集中计算；跨类目取其唯一抽样归属组的百分位。
- 同值使用平均名次；整组同值时不制造高低差异，同分按固化种子排序。
- 保存原始点击数、抓取时间、比较组大小及百分位。缺失计数不当作真实零值；可进入随机池，不优先进入热度池。
- 不新增源站刷新请求。历史抓取快照曝光时长可能不同，页面说明这是近似热度比较，不是曝光归一化后的点击率。
- 热度只影响选样，不进入模型技术质量打分，不设置“低 star 淘汰”规则。

## 4. 模型处理与输出契约

### 4.1 分批提取

按固定顺序每批最多 10 篇，最多四批；按配置上下文限制验证请求是否可容纳。超过限制时减少本次实际样本并明确报告，不增加无限批次。

新 Prompt 类型建议为 `direction_exploration_extract`。每批输入包含原始论文快照与已有方向定义，输出结构化 JSON：

- 每篇论文的 `paper_id`、研究问题、核心方法、新能力或应用、摘要能支持的局限。
- 零到三个可能共同观察的论文组合，包含论文 ID 和共同问题描述。
- 必须覆盖该批全部输入论文且每篇恰好一次，不得引用批次外 ID。
- 区分作者宣称与摘要可核对的证据；不凭摘要断言已复现、商业成熟或具备投资价值。

### 4.2 周报汇总

新 Prompt 类型建议为 `direction_exploration_synthesis`。输入为通过校验的批次结果、对应论文快照、启用方向及最多 20 个观察／忽略候选的简短历史定义。

候选输出字段：

| 字段 | 要求 |
|---|---|
| `name`、`scope_text` | 可理解的候选名称与范围，说明研究问题及边界 |
| `signal_type` | `multi_paper` 或 `single_paper` |
| `paper_ids` | 多篇信号 2–5 篇；单点信号恰好 1 篇 |
| `why_now` | 当前样本出现的能力变化或共同问题，不伪造增长趋势 |
| `difference_from_existing` | 对已有方向的差异；可以是子方向，不要求完全脱离已有研究 |
| `evidence_gaps` | 尚未验证的实验、独立性或应用假设 |
| `prior_candidate_ref` | 已观察候选的引用，或空值 |
| `relation_to_prior` | 新候选／更新观察／重复忽略候选 |
| `new_evidence` | 更新观察或重提忽略候选时的具体新增证据 |

总候选最多三个，可为空。引用只能来自本次成功提取论文或输入中明确提供的观察候选历史证据，并区分新证据与历史证据。论文内容视为数据，不执行其中的指令。

多篇论文不等于多个独立团队。作者重叠由程序展示；摘要缺乏机构或贡献角色证据时，不输出“多个独立团队确认”。单点信号只建议观察，不使用已形成研究趋势的表达。

按规范化名称去除完全重复候选；语义近似由汇总模型辅助判断。忽略候选没有新证据时隐藏并计数；观察候选更新时关联已有候选，而不是反复新建同名方向。首版不承诺完全消除语义重复。

### 4.3 成本、失败与恢复

- 正常最多五次逻辑调用；输入为零时零调用。仅一批时为一次提取加一次汇总。
- 每个逻辑阶段最多两次物理请求，任务合计最多十次。包括网络重试、格式回退及 provider 并发降档重发；不得与外层重试相乘。
- 复用调用账本与 provider 并发闸门，首版提取串行执行。若现有底层不能传递统一请求预算，开发时先补预算控制，不把“五次”写成实际请求硬上限。
- 每次提取输出上限默认 1,000 tokens，汇总默认 2,000 tokens，正常输出上限合计 6,000 tokens；十次均耗尽时最多 12,000。实际输入／输出和请求次数进入任务记录，成本按实际模型价格另算。
- 提供独立探索 Profile 选择；缺少 Profile／Prompt 时预览提示并阻止入队，不静默使用昂贵全文模型。
- 结构错误、未知引用、缺失论文或超出候选数上限时整次输出无效，不保存部分合法候选。
- 部分提取批次失败时允许汇总成功批次，周报标为 `partial_success`，展示实际覆盖数及失败批次；全部失败则不调用汇总。
- 汇总失败时保留已成功提取结果，显式重试仅执行失败阶段。原任务生命周期内仍共用十次总预算；耗尽后显示失败，不自动新建任务。
- 提供使用既有成功提取结果的显式“重试汇总”入口，作为关联重试任务，预览新增上限两次物理请求；不重发成功提取。禁止无提示自动续费重试。

## 5. 页面与人工处理

### 5.1 预览及周报

新增“新方向探索”入口，单页面包含生成预览、周报历史及候选卡片；周报详情可用同页面详情区实现。

预览展示日期窗口、合格／排除数量、三组实际样本数、预计批次数、最大请求次数和所选 Profile。点击生成即授权本次有限调用，无需逐次确认。

周报展示选样构成、实际成功论文数、失败情况、调用量及零候选原因；可展开样本论文和抽样理由，便于检查遗漏。标题使用“候选方向”，不使用“已确认新趋势”。

### 5.2 候选处理

- **继续观察**：保存状态，可填写判断；后续周报携带简短定义及历史证据。
- **加入关注方向**：跳转现有创建表单并预填名称及范围，用户可编辑；提交成功后关联方向 ID 并标记已加入。点击预填按钮本身不创建方向。
- **忽略**：理由必填，用于抑制重复推荐；历史记录仍可查看，可改回观察。
- 尚未处理为 `pending`，状态为 `pending / observing / added / ignored`。人工状态修改须保存时间与理由，不覆盖模型原始推荐。
- 已加入候选显示方向链接。目标方向归档后保留历史关联，不自动重新创建方向。
- 保存已有方向与候选关联可在同一事务完成，重复提交不得创建两个方向；名称冲突回到现有校验流程，不自动改名。
- 加入方向后提供现有历史补分类入口，默认建议回溯最近 30 天。预览及确认沿用已有入口，创建方向不自动触发补分类。

## 6. 存储及现有模块衔接

首版建议只新增一个 `direction_exploration_runs` 表，沿用 SQLite 版本化初始化。字段建议如下：

| 字段组 | 内容 |
|---|---|
| 身份 | ID、关联 job_id、日期窗口、幂等键、关联重试 run_id |
| 计划快照 | 输入论文、抽样理由与种子、方向定义、历史候选、Prompt／Profile／模型标识及版本 |
| 执行结果 | 各批状态与校验后提取、汇总结构、最终周报、覆盖数量、失败原因 |
| 人工处理 | 最多三条候选的本地稳定 ID、状态、理由、方向关联及处理记录 |
| 审计 | 输入指纹、schema 版本、调用统计、创建／完成／更新时间、行版本 |

低频小数据用 JSON 列保存快照与候选，不新增一组论文关系表。候选引用采用 `run_id + candidate_id`，不能依靠模型名称做身份标识。历史候选从近期记录按更新时间取最多 20 个，观察优先，再取忽略；已加入候选由当前方向快照覆盖。

默认页面只分页展示周报概要，按需加载完整快照；按日期、状态及 job_id 建索引。成功探索论文排除集合可先读取近期成功提取记录并缓存到任务内；不逐篇查询。数据增长后再按测量结果决定拆表。

现有任务中心新增 `direction_exploration` 类型，记录计划、提取、汇总及完成事件。模型物理请求仍由现有账本保存，不在新表存 API 密钥。不得把探索提取伪装成 `abstract_review` 成功，也不得建立现有方向分类关系。

建议服务／数据库边界：新增 `exploration.py` 和 `exploration_db.py`，路由只负责校验、预览、入队及展示；复用现有 jobs、Prompt、LLM 和表单能力。Prompt 类型和任务处理入口需做明确注册。

### 幂等与并发

- 同一日期窗口已有运行中或成功周报时默认返回已有记录，不重复调用；部分成功／失败显示明确恢复入口。
- 开始执行前固化输入，不受后续抓取、方向变更或 star 更新影响。预览与执行样本发生变化时，以入队快照为准并展示实际计划。
- 保留成功批次和请求用量检查点，进程中断恢复不重发已确认成功的阶段；未知请求状态沿用现有调用恢复语义，不伪造成功。
- 更新 JSON 人工状态用事务与行版本校验，避免两个页面操作覆盖彼此。用户处理与后台结果分别更新，不整行覆盖。
- 本功能不自动设置调度器、不刷新正式源站、不读取或修改全文缓存；模型调用在数据库写事务外执行。

## 7. 验收标准

全部测试使用临时数据库及 mock provider，不调用正式模型或改动正式研究数据。

1. 正常 40 篇按 20／10／10 构成，跨类目与跨组无重复；同一快照及种子选样一致。
2. 边界覆盖无启用方向、零论文、组不足、零／缺失 star、分类失败、跨日时区及超长摘要；不静默扩窗。
3. star 只影响热度组选样；零 star 论文仍可被随机选中，不参与技术质量加权。
4. 不下载 PDF、不生成 Markdown、不调用全文评估，不写摘要评估成功或方向分类结果。
5. 正常最多五次逻辑／十次物理请求，重试、格式回退和并发限流场景均验证总预算不会超出。
6. 模型未知 ID、缺失批内论文、重复引用、候选超限和结构错误被拒绝；零候选成功可正常展示。
7. 部分提取失败显示覆盖不足；汇总失败保留成功提取；恢复、重复点击和进程中断不会无界重复消费。
8. 观察／忽略候选可关联回溯；没有新增证据的重复忽略候选不重新推送；单点信号不包装成多团队趋势。
9. 加入方向先预填，提交后才创建；重复提交、名称冲突、已有方向归档及人工状态并发更新处理正确。
10. 周报和论文引用可打开，快照和调用账本可回查；列表分页，不一次加载全部历史快照。

## 8. 实施顺序与四周试用

| 阶段 | 内容 | 完成依据 |
|---|---|---|
| E0 | 表结构、版本化初始化、确定性选样和零调用预览 | 选样与迁移边界测试通过 |
| E1 | 两份 Prompt、任务处理、结构校验、调用预算和恢复 | mock 全链路与异常预算测试通过 |
| E2 | 周报页面、候选状态、预填现有方向表单 | 页面与重复提交流程验收通过 |
| E3 | 人工每周运行，连续四周 | 保存周报、人工处理及调用统计，复盘选样价值 |

试用每周记录：实际探索论文数、候选数、继续观察数、加入方向数、忽略及重复候选数、审阅分钟数、物理请求数与实际 tokens。候选多或 star 高不作为成功标准。

四周后重点判断：是否产生此前关注方向未覆盖且用户愿意继续研究的候选；是否能在约 10 分钟内完成审阅；重复与泛化候选是否挤占名额。样本量很小，不据此宣称统计显著或证明某种算法更优。

根据具体问题调整样本比例、Prompt 和候选卡片；仅当遗漏或重复证据明确时再考虑嵌入聚类、长期趋势或自动周调度。首版不预设必须升级。

## 9. 首版范围之外

- 跨全站或未采集学科发现；实时追踪 star 增量或曝光归一化。
- 自动技术质量评级、投资结论、团队独立性确认和商业化验证。
- 自动新建关注方向、投资主题、收藏或备忘录，自动历史补分类。
- 向量检索、复杂聚类、趋势增长显著性计算、外部论文／公司搜索。
- 自动发送周报或定时付费调用。
