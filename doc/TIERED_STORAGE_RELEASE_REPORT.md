## 1. 已实现行为

| 项目 | 当前行为 |
|---|---|
| 元数据与证据 | 保留论文元数据、原始摘要、分类、评估、人工状态及历史备忘录；缓存清理不删除这些记录 |
| 普通缓存 | PDF 7 天；Markdown 30 天 |
| 核心缓存 | PDF 30 天；Markdown 180 天；均为可到期缓存 |
| 核心判定 | 收藏、投资主题关系、团队 tracking、成功备忘录版本引用的并集；返回理由 |
| 历史归档 | 主题归档、作者／机构归档及备忘录系列归档不抹去仍成立的核心依据 |
| 使用计时 | PDF 实际打开、Markdown 实际读取、成功 PDF 转换分别记录；存在检查及列表不写时间 |
| 升级窗口 | 业务事务内比较等级，只在普通→核心时更新 `tier_promoted_at`；新增另一核心理由不重复延长 |
| 旧缓存 | 只登记可映射的有效文件，给予一次性宽限；重复启动／登记不刷新宽限；无效／孤立文件统计并跳过 |
| 缺失缓存 | 单独的“下载／重新生成全文缓存”任务，不调用模型，不重评历史结果；PDF 支持浏览器范围请求 |
| 全量采集 | 明确日期，先取得 Total，再请求对应 show 数；核对日期、标题条目数、有效唯一 ID、重复与缺失 |
| 异常采集 | Total 未知或变化、日期异常、缺漏、重复及 10,000 篇资源上限均不可标为全量成功 |
| 业务门控 | 继续沿用关注方向及摘要候选规则；采集本身不批量下载 PDF，不新增隐式 LLM 请求 |
| 界面与诊断 | 四项期限、核心理由、北京时间使用／到期时间、独立 DB／PDF／Markdown 占用、清理数量／字节／跳过／错误统计 |

四项新设置为唯一清理依据。旧全局键保留原值供回退，设置表单不覆盖它们。修改期限或研究状态在下一轮清理生效；降级后的旧缓存可能立即到期。

## 2. 数据库及并发设计

新增 `paper_cache_artifacts` 和版本标记 `tiered_cache_v1`，记录缓存键、类型、论文关联、来源版本、生成／实际使用／迁移宽限／核心升级时间及字节数。未确认的来源版本为 `unknown`，不把旧无版本文件宣称为某个新论文版本。

迁移在现有初始化入口执行，使用保存点，保留既有新设置。新增 `categories.collection_mode`；迁移旧类目为 `top_n`，旧任务快照也继续按原模式运行。新建类目界面默认选择 `full`。已有类目须在类目管理选择“每日全量”并保存；更新代码不会擅自扩大现有任务范围。

清理先分批查询核心状态和账本，只对到期候选取得缓存锁。锁内启动短 `BEGIN IMMEDIATE`，复查最新等级、期限、使用时间与文件身份，再删除文件和登记行。下载、转换、模型调用及全目录扫描均不在该写事务内。

配置缺失／无效、迁移缺失及核心 SQL 失败停止后续删除。文件占用／权限错误保留账本。若 unlink 成功后数据库回滚，下次盘点可修复过期且文件缺失的登记行；这不是文件系统与 SQLite 的跨资源原子提交。

成功使用时间按 60 秒节流；最短 TTL 为 1 天，节流发生时旧 TTL 至少剩余 23 小时 59 分钟。新文件生成不受该节流抑制。缓存命中及失败转换不会伪造使用时间；成功下载后登记失败不会触发第二次 HTTP 下载。

1. 按 [架构发布说明](ARCHITECTURE_RELEASE_NOTES.md) 停止旧运行时，备份主库、Profile 库及解密材料，保存启动／每日清理开关。
2. 启动新版现有入口；持有 workspace lock 后执行迁移和旧缓存登记。新四项默认 7／30／30／180，已设置的新值不覆盖。
3. 检查设置、核心理由及旧缓存宽限。需要每日全量的既有类目选择 `full`；观察首次任务的数量／日期／缺失指标。
4. 回退先停机，保留研究记录和备份。运行旧代码前关闭 `cache.cleanup_on_start` 和 `cache.cleanup_daily`，避免恢复旧短期限删除；保留原开关便于再次升级。数据库备份不会恢复已删除的全文文件。

本轮仅验证隔离升级、重启和备份回退；没有对正式数据库迁移，没有启动正式抓取、清理或 LLM 任务，没有提交／推送 Git 变更。匹配旧 S4 源码的历史恢复样本缺失仍独立列为未验证项。
