# 轻量新方向探索：实施与验收

- 日期：2026-10-09（北京时间）
- 依据：[轻量新方向探索 PRD](PRD_轻量新方向探索.md)
- 状态：E0–E2 已实现并完成隔离验证；E3 四周人工试用尚未开始。

## 已实现

主导航新增“新方向探索”。最近七个完整北京时间自然日内首次入库的论文进入选样，默认最多 40 篇。已有方向启用时按热度／随机／边缘 20／10／10 取样；未设方向时按热度／随机 30／10。跨类目与样本组去重，样本不足显式补位，失败分类不冒充未匹配；已成功提取论文不重复探索。

阅读热度取同类目、同源日期的近似百分位，只影响选样，不提供给模型作为质量证据。原始点击数、比较组及抓取时间保留在计划快照中。历史库已保存为零的缺失计数无法反推真实缺失；相同热度使用固化种子打破平局，因此没有热度差异时不会伪造排序差异。

两个独立探索 Prompt 可编辑、绑定模型；页面可选择独立探索 Profile，未配置时阻止有论文的任务入队。论文原始摘要分批提取，再汇总最多三个候选；合法零候选可正常显示。只引用已校验论文与历史观察证据，不下载 PDF、不转换 Markdown、不写摘要评估成功或既有方向分类。

候选支持继续观察、填写理由后忽略、预填现有方向创建表单。确认保存时方向创建与候选关联同事务完成，重复提交不重复建方向。观察候选更新关联历史，旧卡片指向后续周报；人工操作保留历史及行版本检查。加入方向后可预览最近 30 天历史补分类，但不自动执行。页面提供人工审阅分钟数及处理数量，供四周复盘。

## 调用与恢复

正常最多五次逻辑调用；每阶段最多两次物理请求，原任务总预算十次。HTTP 边界在发送前持久化扣减预算，涵盖网络重试、格式回退和 provider 并发降档；探索本身关闭 response-format fallback。正常提取／汇总输出上限为 1,000／2,000 tokens。

每个成功批次单独保存。部分提取失败时仅汇总成功论文并标明覆盖不足。显式恢复保留原任务已消费预算和成功检查点；预算不会因进程或 job 重试重置。另有“只重试汇总”关联入口，复用提取并新增最多两次请求；存在结果未知请求时需明确确认可能增加费用。

这里的预留次数是保守请求预算：如果数据库登记在真正发出 HTTP 前失败，也可能已占用一个预算名额；调用账本中的物理请求及实际 token 独立展示。不把预留次数当成精确付费次数。

## 使用方法

1. 重启现有应用，通过正常初始化迁移新增周报表与两个默认探索 Prompt；已有 Prompt 内容不会被覆盖。
2. 打开“新方向探索”，选择启用的独立探索模型；Profile 必须配置上下文上限。也可在 Prompt 管理分别绑定提取和汇总模型。
3. 查看日期、样本构成和请求上限，每周手动生成一次。任务运行中可打开任务详情；完成后刷新周报查看结果。
4. 对候选继续观察、忽略或编辑范围后加入方向，记录审阅时间。按需手动预览历史补分类。

## 边界与后续

- 只探索已采集范围；没有启用方向时无需既有分类。有方向时，缺失／失败分类需先通过已有流程处理。
- 上下文采用现有估算器检查，不保证精确 token 数；过长论文明确跳过，汇总超限则保存提取并显示失败，不静默截断原始摘要。
- 模型的候选去重和方向判断仍需人工审阅；摘要不能验证实验复现、团队独立性或投资价值。
- 首版未配置自动周调度或通知；四周后根据观察／加入方向数、审阅时间与重复推荐复盘，再决定是否扩展。

实现入口为 `exploration.py`、`exploration_db.py` 和 `exploration_routes.py`；复用现有 jobs、Prompt、LLM、调用账本及方向表单。
