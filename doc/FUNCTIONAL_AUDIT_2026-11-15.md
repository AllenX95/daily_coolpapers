## 已复现缺陷

**F1 高优先级 · 北京时间选样窗整体提前 8 小时。** 固定探索日期为北京时间 2026-10-08，用标准 `db.upsert_papers` 按其真实入库字段格式分别产生本地无偏移 `2026-09-30 20:00:00` 与 `2026-10-07 20:00:00`，打开 `/direction-exploration`。页面日期为 10-01 至 10-07，预期仅后者入样，实际仅前者。真实写入的 `db.now_iso()` 产生无偏移本地时间，探索把窗口换为 UTC 后直接用 SQLite `julianday` 比较。旧测试注入带 UTC 偏移时间，未覆盖当前写入格式。见 [写入函数](../daily_coolpapers/db.py#L89) 和 [探索查询](../daily_coolpapers/exploration.py#L82)。

**F2 高优先级 · 汇总模型上下文不足时预览仍允许消费提取预算。** 在隔离库造 20 篇、每篇 500 字符原始摘要，提取 Profile 上下文 65,536，单独给汇总 Prompt 绑定上下文 2,600、输出预留 2,000 的 Profile。真实 `GET`／`POST /direction-exploration` 预览 20 篇、2 批、3 次逻辑调用并成功入队。worker 实际完成两次 mock 提取，汇总未发请求即报 `exploration_context_exceeded`，周报失败，20 篇已标记为消费。原快照重试仍受同一上下文限制。应在提取前体现汇总上下文约束和实际可用样本。见 [计划和执行](../daily_coolpapers/exploration.py#L161)。

**F3 中优先级 · 新采集缺失热度被当作真实零，重抓计数的时间仍指向首次记录。** 在同类目同源日期插入一篇无计数论文、一篇明确 PDF/Kimi 均为 0 的论文，两篇均进入热度组，百分位均为 0.5、比较组均为 2；源站解析辅助函数对缺失标签也返回 0。第二天重抓第一篇并将点击数从 0 更新到 10，计划的 `heat_captured_at` 仍为第一天。PRD 要求缺失可进随机池且保留对应抓取时间，问题也影响当前新增数据。见 [计数解析](../daily_coolpapers/crawler.py#L782) 和 [入库更新](../daily_coolpapers/db.py#L1102)。

**F4 中优先级 · 已明确命中的论文在另一方向缺结果时被排除。** 启用两个关注方向，对论文只保存第一个方向的 `matched`，检查现有方向判定 `effective=True`。打开探索预览，实际计入“分类待完成”并从边缘样本排除。PRD 对部分缺失的排除条件为无法确定有效聚合，已有有效命中的论文满足 `matched`。见 [探索聚合](../daily_coolpapers/exploration.py#L115)。

**F5 中优先级 · 重新汇总后原候选 ID 可以指向另一候选。** 隔离库通过 `validate_synthesis` 与生产持久化函数写入部分成功周报，候选顺序 Alpha、Beta；表单将 ID 1 的 Alpha 设为观察。再用同一周报的生产结果持久化函数保存模拟的恢复汇总 Beta、Alpha。实际 Alpha 仍保留观察状态但变为 ID 2，原 ID 1 指向 Beta。该复现覆盖结果写入与真实人工表单，未依赖 Provider 或执行完整进程恢复。按 PRD，`run_id + candidate_id` 的历史引用应稳定。见 [候选 ID 分配](../daily_coolpapers/exploration.py#L244) 和 [恢复保存](../daily_coolpapers/exploration_db.py#L137)。

## 发布判断和剩余证据

1. 生产发布先在现有数据工作区的停机备份基础上验证 Profile 解密、正常启动顺序和清理行为。正式目前 `cache.cleanup_on_start=true`、`cache.cleanup_daily=true`、`scheduler.enabled=true`。源码启动，在工作区锁内依次执行迁移、旧文件登记和启动清理，随后启动 worker／调度。迁移会保留开关现值；真实上线前应确认拟保留的开关、登记宽限、实际目录和第一轮清理指标。用旧版本回退时，按发布报告关闭旧版启动／每日清理或使用兼容回退包。
2. 迁移完成后，所需旧类目手动切换每日全量，通过第一轮任务详情记录源日期、应抓、解析、唯一、缺失、入库；随后确认定时维护和任务诊断。历史源站两样本不足以证明当前持续覆盖。
3. 先修复探索的选样边界、预算预检与候选身份等风险并补足对应回归，再启动 E3 四周试用。每周记录覆盖、候选及人工处置、审阅时长、调用量和实际 token，评估是否发现愿意继续研究的方向。
4. 另外保留待验证项：正式 Profile 连接与实际模型输出、长期占用、首页大规模延迟、休眠恢复、匹配 S4 回退材料。仓库改动仅本验收文档。
