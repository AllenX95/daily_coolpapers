## 1. 目标与当前状态

正式数据库已于本日升级为当前 schema，旧业务数据已清空；类目、Prompt、模型配置及密钥保留。数据库升级不再列为本轮待修任务，也不重复清库。当前服务未启动，类目仍为 `top_n`。F1–F5 均未修复。

## 3. 统一约束

1. 探索仅使用元数据、原始摘要及已有分类，不下载全文，不自动补分类，不生成普通摘要评估。
2. 正常最多 40 篇、4 批提取加 1 次汇总、最多 3 个当前候选；原任务物理请求累计最多 10 次，各阶段最多 2 次。恢复不重置预算。
3. 预览零模型调用。入队固化实际计划、Profile/Prompt、输入及预算。后续配置变更不得静默改变运行中任务。
4. 成功提取检查点保留；只有已成功提取的论文计入消费，计划裁减、预检阻止或提取失败的论文不计入消费。
5. 人工状态及历史证据不得因后台恢复丢失，写操作继续使用 CSRF、事务、行版本校验与幂等控制。
6. 测试使用临时库和模拟 Provider。数据库迁移可重复执行，不改写模型配置、人工记录及旧周报快照，不再次清空正式库。

## 4. R1：统一时间语义

### 问题

真实入库保存本地无偏移时间，探索用 UTC 查询边界直接比较，导致北京时间窗口提前 8 小时。页面日期与实际选样不一致。

### 目标行为

- 基准时区固定为 `Asia/Shanghai`，不随执行主机时区改变。探索日期为 D 时，窗口为北京日 `[D-7 00:00, D 00:00)`，不含当天。
- 查询统一按时间点比较。新增首次入库时间应具有明确偏移或使用明确的 UTC 存储约定；重复抓取不改变首次入库时间。
- 兼容现有明确偏移的 ISO 时间及本项目既有无偏移本地格式。当前已知中国时区数据的无偏移值按北京时间解释；不得把所有明确偏移值再加减 8 小时。
- 对无法解析的值显式计为时间异常并排除；不自动赋成当前时间。外部导入或其他主机产生且时区未知的数据需要明确来源时区，不猜测。
- 优先在论文首次入库字段和探索查询边界内修复。若修改共享时间函数，必须检查任务调度、缓存到期、日志和其他比较逻辑，避免全局时间语义回归。

### 验收

| 编号 | 场景 | 必须结果 |
|---|---|---|
| R1-01 | D=2026-10-08，标准入库写入 09-30 20:00 与 10-07 20:00 北京时间 | 仅后者入样 |
| R1-02 | 起始边界前一秒、边界本身、结束边界前一秒、结束边界本身 | 依次排除、纳入、纳入、排除 |
| R1-03 | 相同时间点分别用 UTC、+08:00 和旧无偏移格式表示 | 资格一致 |
| R1-04 | 改变主机时区，重复抓取，跨月/年窗口 | 窗口和首次入库资格保持正确 |

## 5. R2：提取前验证汇总容量

### 问题

提取模型可容纳任务不代表汇总模型可容纳。当前 20 篇样本可完成两次提取，随后才发现汇总上下文不足。

### 计划与预览要求

- 计划同时解析实际生效的提取和汇总 Profile/Prompt，不假定两者上下文相同。
- Profile 保存模型的上下文和输出上限。探索单次提取最多预留 1,000 tokens，单次汇总最多预留 8,192 tokens。Profile 输出上限较低时采用较低值。已知官方端点还受该端点公布的上限约束。上下文按输入与预留输出合计计算。预览估算、入队快照和实际请求使用同一任务预算，已有快照沿用当时的输出预算。[模型参数核验](MODEL_TOKEN_LIMITS_2026-11-16.md)
- 两阶段分别估算：系统指令、渲染 Prompt、固定上下文、论文/方向/历史候选输入、消息结构开销、输出预留及明确的安全余量。汇总还须预留各提取批次允许返回的最大结果体量；估算项不得重复累计。
- 复用当前 token 估算器，页面标注“估算”；不承诺精确 Provider token 数。即使预检通过，执行前也要检查实际汇总输入。
- 汇总固定开销已超过预算时，直接阻止入队、显示模型及可用容量不足原因，零提取请求。
- 样本造成容量不足时，沿用固定种子和确定性规则逐步减少样本并重新计算两阶段计划；不截断原始摘要，不扩大窗口，不增加超过四批的提取。
- 预览展示原合格数、最终样本数、因容量跳过数、批次数、逻辑调用数、物理请求上限和两阶段模型。无样本可执行时禁止生成。
- POST 及 worker 调用前再次校验冻结计划。若计划变化，保存并明确展示实际执行计划；不能继续沿用过期预览的数量承诺。

### 失败与恢复要求

- 运行时发现实际汇总输入超限，保存成功提取检查点，记录具体阶段和容量原因，不重发提取、不静默截断，也不自动续费。
- 已成功提取仍按原契约计入消费；页面区分“已提取”与“周报已生成”，提供恢复入口，避免用户误以为重新生成会重读这些论文。
- 原任务恢复保持原配置快照及剩余预算。对已知不可能通过的原配置，提示配置问题，不重复提交同样的无效模型请求。
- 显式“重试汇总”允许用户选择容量足够的汇总配置，重新预检后创建关联重试快照，保留原任务历史，最多新增两次物理请求。复用成功提取结果，不调用提取；结果未知请求继续沿用费用确认规则。

### 验收

| 编号 | 场景 | 必须结果 |
|---|---|---|
| R2-01 | 20 篇×500 字符；提取上下文 65,536；汇总 2,600、夹具 Profile 输出上限 2,000 | 提取前阻止或明确裁减为可执行计划，不再两次提取后才发现可预知的超限 |
| R2-02 | 固定上下文已超限；裁减后零篇 | 零模型请求、零论文消费，页面解释原因 |
| R2-03 | 容量充足、40 篇正常路径 | 仍最多五次逻辑调用；原请求预算约束不变 |
| R2-04 | 实际结果造成运行时超限 | 成功检查点保留；无额外提取；可见明确失败原因 |
| R2-05 | 改用较大汇总配置显式重试，重复提交/中断恢复 | 新快照可追溯，最多两次新物理请求，无重复提取 |

## 6. R3：区分未知热度并记录正确采集时间

### 数据及选样规则

- PDF/Kimi 点击数分别保留“未知”和非负整数；缺失标签、空值或无法解析不得默认写成 0。明确显示的 0 是有效观测。
- 仅当两个分量均已知时，组合 `reading_stars` 才为有效总数。任一分量未知时，组合值未知，不将已知部分冒充总数。
- 热度百分位的比较组仅含该类目、同源日期内有效计数的去重论文。未知值不计入分母、不参与热度优先选样；仍可按所属资格进入随机或边缘样本池。
- 整组同值继续使用平均名次及固化种子，不人为制造热度差异；比较组为零时无百分位。
- 同一来源观测的计数、有效性和 `heat_captured_at` 原子更新，保留首次入库时间。重复抓取计数未变也要反映本次实际观测时间。
- 新抓取缺失计数时，当前观测应标为未知，不拼接上一轮的计数与本轮时间；如保留上次有效值，须独立保存其旧时间且不冒充当前值。
- 无法从历史数据恢复的缺失/零语义使用兼容标记，不推断历史零值为已知；未经新观测确认的遗留热度不优先进入热度组。不自动刷新源站补数据。
- 列表、详情、导出和探索对未知值显示“未知”或空值，排序不会报错；历史冻结周报保持原样。

### 验收

| 编号 | 场景 | 必须结果 |
|---|---|---|
| R3-01 | 一篇缺失、一篇明确双零 | 仅双零参与有效热度比较；未知可进入随机池 |
| R3-02 | 单字段缺失、解析失败、正值、全组未知 | 有效性及比较组大小符合上述规则，无异常 |
| R3-03 | 次日从 0 更新至 10；数值不变重抓 | 观测时间更新，首次入库时间不变 |
| R3-04 | 有效值后收到缺失值；迁移旧零记录 | 不出现新时间配旧计数，不伪造观测真实性 |
| R3-05 | 新旧 schema、显示与导出 | 重复迁移成功，未知值正确展示，历史快照不变 |

## 7. R4：复用有效方向聚合规则

先应用当前启用方向快照、有效分类版本及人工确认/否决，再聚合。结果完整性和已确定的匹配资格分开记录；明确命中不能因无关方向缺失被覆盖。

| 有效结果组合 | 探索聚合结果 | 池资格 |
|---|---|---|
| 任一明确有效 `matched`，其他方向任意或缺失 | matched | 边缘池 |
| 无 matched，至少一个有效 possible，其余均有有效结果 | possible | 边缘池，按原规则优先 |
| 无 matched，possible 与缺失/失败并存 | 分类待完成 | 暂不入池，避免把尚未确定的聚合当作完整分类 |
| 全部启用方向有有效结果且均 unmatched | unmatched | 热度/随机池 |
| 无有效命中且部分/全部缺失或失败 | 分类待完成 | 暂不入池 |
| 无启用方向 | 未设方向探索池 | 原 30 热度/10 随机规则 |

人工确认形成的有效命中按 matched 处理；人工否决撤销该方向命中，但不能否决其他有效方向。停用方向不参与当前聚合。探索不得为补齐结果额外调用分类模型。

验收至少覆盖：matched+缺失、matched+失败、人工确认+缺失、被否决命中+缺失、全 unmatched、possible+完整结果、possible+缺失、全缺失、停用方向和无方向。验证池资格和统计数量；有资格不等于一定抽中。若公共有效判定有更细语义，实施时统一公共契约并同步本表，不能仅在探索中新增一套矛盾规则。

## 8. R5：候选稳定身份与恢复保存

### 身份契约

- 候选首次持久化时分配本地 ID；显示顺序独立保存。ID 不使用数组位置、规范化名称或模型自行编造的值作为唯一身份依据。
- `run_id + candidate_id` 永不重新分配给不同候选。观察/忽略理由、方向关联、操作历史均按此身份维护。
- 恢复汇总输入携带已发布候选身份和内容；输出若延续旧候选，须明确引用输入中存在的身份。引用重复、未知或与所属周报不符时整次保存失败，保留旧结果。
- 相同结构内容仅顺序变化时保持 ID；可用规范化完整内容指纹做精确重排匹配，不能只按名字判断。改名或内容改变需明确延续引用；无法确认身份时分配新 ID，不转移旧人工状态。
- 新汇总不再包含的旧候选保留为历史/已被替代记录，原链接仍能展示原内容。当前候选最多三个，历史记录不占当前名额。
- 同一候选的模型内容更新须可回查此前版本，人工判断独立保留。历史内容及来源证据不因重试被静默覆盖。

### 并发与兼容

- 候选映射、模型结果及版本更新同事务提交；后台保存不能覆盖期间产生的人工操作。
- 旧表单行版本失效时返回明确冲突，不能把操作应用到同位置的新候选。
- 旧数据迁移保持已存在的 ID 与当前对象绑定；无可靠证据不能“修复”已发生的历史错位，应保留并标记不可确认情况。正式探索表虽为空，仍须用旧格式夹具测试兼容。
- 候选加入方向仍保持幂等，恢复不重复建方向。

|---|---|---|

| R5-02 | 插入/删除候选；改名；同名不同范围 | 不按位置/名称误继承身份；旧链接可追溯 |
| R5-03 | 重复保存、非法延续引用 | 幂等；非法结果原子拒绝，旧结果不变 |
